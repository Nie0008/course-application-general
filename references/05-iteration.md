# 05 迭代与跨材料同步

**输入**：用户反馈、主稿、相关课件和脚本、已认可内容、版本记录。

**执行**：
1. 先分类反馈：事实错误、教学逻辑、工作范围、具体栏目、措辞或视觉。定位不对时回到学习目标；只改措辞时不要重做课程。
2. 文件名“终稿”“最新版”不能证明权威。用用户指定、内容变更、来源记录确认当前主稿。保存基线与改动说明。
3. 精确修改目标。用户只改学生活动列，就给逐环节该列文字；发现教师活动不匹配时说明联动项，不暗改已认可内容。
4. 检查依赖：教学任务变化→教案、PPT、逐字稿、学生手册；目标变化→任务和量规；数据变化→申报书、说课、图表；政策变化→提交清单。
5. 修订记录写“问题、证据、决定、改动、受影响材料、验证结果”。一次意见产生的多个衍生文件使用共同版本标识。
6. 验证针对变化：字段和数字检查、版式检查、平台实测各报其实际范围。完成必要检查即可交付。

**产出**：定向改稿、联动清单、版本记录。保留未解决冲突，不自封终版。

**检查**：原问题已解决；批准过的临近文本未误改；过时案例/数字不残留；不把“审计建议”写成“已实施”。

**可复制指令**：
> 按我这次反馈只修改【栏目/范围】，以【文件】为主稿。保留其余已认可表述。列出修改前后的关键差异，并核对课件、逐字稿、任务书和量规中受影响的内容；未获确认的课程定位变化单独提出，不直接扩写。
